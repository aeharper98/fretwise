# Fretwise project notes

- The whole app lives in `web/index.html` (inline CSS and JS, no build step). Keep it that way until the Capacitor step needs otherwise.
- Pitch, chord and scale data are checked by script: every chord shape in `SHAPES` must spell only its formula's notes. Re-run that check after editing shapes.
- Samples in `web/samples/` are loaded with `fetch` by relative URL, so the page must be served over http(s), not opened as a file.
- Never commit App Store Connect keys (`.p8`), certificates or provisioning profiles. They belong in GitHub Actions secrets.
- iOS: Capacitor 7 with Swift Package Manager. After changing `web/`, the CI runs `npx cap sync ios`; `ios/App/App/public` is generated and not committed. Edit native files (AppDelegate.swift, Info.plist) directly.
- The iOS build cannot be run in a Linux session; it only runs in the `testflight.yml` workflow on a macOS runner.
- The Learn path is `LEARN_ALL` in `web/index.html`. Stage kinds `notes`, `chords`, `bass`, `ear`, `numbers` are handled inline; newer kinds live in the `KINDS` registry (each has `study()` for the stage page and `gen()` for practice questions run by `Life`). Stage ids are stored in progress, so never rename an id; add new ones instead.
- Gap lessons: a stage with `fill:true` teaches something later stages assume (letters on the neck, half steps, the major scale, G and D major in first position). `Learn.nextStage()` puts an unpassed fill stage that sits before the current stage first, and `Learn.after()` picks the Next button after a pass, so someone already past it is sent back for it once. Mark new prerequisite stages `fill:true` when inserting them behind existing ones. `dt` is a description for players who said they know theory (`theoryFluent()`); `dp` is for any pianist.
- Lessons: every stage teaches before it quizzes. `Teach.lesson(st)` builds the steps the first time a stage is practised (`learnProg.taught[id]`; "Go through the lesson again" on the stage page reruns it): `Teach.kinds[kind]` per stage kind, plus `Teach.extra[id]` for ideas a stage needs first (7th and minor chords, the pentatonic, the leaning 4 and 7), then one or two trial questions from the stage that don't count. Step types: `show` (one idea, the neck marked up with `dots`/`rings`/`heat`/`xo`/`ghost`, tappable `sounds`, a `note` line), guided `find` (note question with the answer ringed, `hintOn`), guided `build` (chord with the shape shown, `showOn`), guided runs (`Pos.run`). A show step whose frets span more than a hand position is an `overview` and is drawn on the whole-neck board, whatever the player's view (`Life.syncView`). Every step is marked `lesson` and never counts. When adding a stage kind, add its lesson to `Teach.kinds`.
- Scale walkthroughs: a `notes` stage with `walk:true` (and `pcs`, `range`, `from`, optional `chord`, `shape`, `sname`) is taught before it is quizzed. `Pos.lesson(st)` builds the steps: a `show` step (the shape, one finger per fret, the chord's notes ringed), each octave in two halves with finger numbers and a ring on the next note, the octave from memory, the notes around it, the whole position from memory. `Pos.notes(st)` places each pitch once, on the highest string where it fits. Steps are marked `lesson` and never count toward passing; `learnProg.taught[id]` records that it ran, and "Walk me through it again" reruns it. The stage's quiz then mixes in octaves from memory (`Pos.memoryQ`).
- Scale-in-order questions are `echo` questions with `keep:true`: right notes stay lit (`at` gives their positions for mic answers), a wrong note counts once and doesn't restart, and the prompt names the next step from `steps`/`dir`.
- Mic answers are forgiving on purpose: input is band-limited (65 Hz–1.1 kHz) before YIN; a reading needs two of the last three frames to agree; `Life.listen` answers once per note (a new note name, a fresh pluck from `Mic.lastOnset`, or the same note after a 350 ms gap) and ignores a note still ringing when the question changes. The first wrong note the mic hears on a name/number question gets another try; in scales and echoes, replaying notes already played is ignored and mic slips in a scale don't count. After any answer marked wrong, "I got it right" stays for `UNDO_MS` (4 s) with a countdown, and questions that move on by themselves wait that long. Tapping it (`Life.fixWrong`, using the `undo` record from `progress`) counts the answer right, including the Review re-check (`Review.snap`/`restore`).
- Mic: the app's own notes are ignored by pitch for about a second (`Mic.appNote`, called from `play()`, which also cuts those notes short while listening; tuner reference tones pass `{ keep:true }`). Don't go back to muting the mic for every app sound: that is what made it miss notes.
- Passing: a stage passes when about 90% of the last N answers are right (`passWindow`). Passed stages are re-checked by `Review` on spaced days (1, 3, 7, 16, 35) through Today's practice; two clean re-checks mark them mastered.
- `?fwtest` in the page address exposes `window.__fw` for automated checks; the stage-walk test answers every stage to completion with it.
- Microphone on iPhone: never switch the audio session while listening. In the app the page asks WebKit for `play-and-record` from the first tap (matching AppDelegate); in browsers it uses `playback` until the mic is first used, then stays on `play-and-record`. `Mic` builds its analyser on its own AudioContext made after `getUserMedia`, and rebuilds the input if it reads exact zeros for about 1.2 s.
- TV / AirPlay: `AppDelegate.swift` gives an external screen its own window with a second WKWebView loading `public/index.html` with `window.__FW_DISPLAY = true` (the `TVView` display mode; `?display` does the same in a browser). The phone page's `TV` object posts a JSON snapshot to the `fwDisplay` message handler about 8 times a second while `__fwScreen(true)`; the TV page answers `ready` on `fwTV` and draws it with `drawMarks`/`renderPiano`. Life's canvas picture is mirrored as board marks by `Life.tvMarks()`; keep them in step when changing `Life.draw`.
- Drive mode (`Drive`, Practice tab): audio-only practice for the car. It speaks a question (Web Speech), plays the sounds, waits `S.drive.think` seconds, then says the answer; topics come from passed stages. A real CarPlay app needs an Apple-granted entitlement even for TestFlight, so Drive mode instead makes Fretwise the Now Playing app: the page posts its state on `fwDrive`, and `AppDelegate` switches the audio session to non-mixed `.playback`/`.spokenAudio`, sets `MPNowPlayingInfoCenter` (shown on CarPlay's Now Playing screen) and maps `MPRemoteCommandCenter` next/previous/play/pause to `window.__fwDrive`. It runs in the foreground only (no background audio mode, so the mic can never stay live with the phone locked); leaving the app pauses it. `wantSession()` returns `playback` while it runs, and it never uses the microphone.
- Key finder (`KeyFind`, Tune tab): listens to a song through `Mic.keyAn()` (a 16384-point analyser on the raw input), folds the strongest spectral peaks between 80 Hz and 2 kHz into 12 note names per frame, and correlates the total with Albrecht–Shanahan major/minor profiles that have each note's overtones (a 5th and a major 3rd up) folded in; without that the answer drifts to the 5 key. It prefers the relative major when the minor is only slightly ahead. Misses on test songs were relative-key swaps, which share capo positions, so the card always offers the relative key. `positions()` gives the G, C and D positions (home chord G/C/D, or Em/Am/Bm in minor) with the capo fret, easiest first. It shares the mic with the tuner: stop the mic only when `Mic.subs` is empty.
- Whole-neck practice: `S.life.flat` (the "Whole neck" button in Life) moves the page's `#board` SVG into `#lflat` between Life's panels, sizes it with `geom(v, fit)` and draws `Life.tvMarks()` on it; board taps go to `Life.cell(s, f)`, the same handler as canvas taps. So `tvMarks()` is also the phone's picture in that mode: every question mode must show up in it. `Life.close()` puts the board back.
